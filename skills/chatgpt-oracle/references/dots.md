# Dots 委派通道

Dots（`https://chatgpt.com/dots`）不是聊天页面，是一个**常驻的、有自己的真实浏览器和文件系统的外部承揽者**。人类可以直接和它对话，Codex 也可以通过桥接向它下发分阶段任务，并通过 WebSocket 收到它推进过程中的状态和产物。

一句话区分：**Oracle 是"问答"，Dots 是"承揽"。** Oracle 的边界是模型上下文，Dots 的边界是它自己的执行环境和时间。

## 什么时候用 Dots

只有当任务需要下列至少一项时：

- **真实浏览器 / 真实环境**：目标页面有登录墙、Cloudflare、反爬、需要点击展开、需要滚动加载、需要下载安装包后实际运行验证。内置网页浏览只取一页文本，做不到这些。
- **跨天推进**：任务不能在一次回答里结束，需要隔一段时间继续，且上下文不能丢。
- **分阶段交付**：每个阶段有独立交付物、独立证据、独立验收条件。
- **项目级持久状态**：需要维护一个工作目录、一份进度文件，跨会话存活。
- **中途可干预**：需要在它工作期间插话、改向、打断。

典型：宽口径竞品调研（给几个名字，它自己去官网、下载、截图、对比）、需要长期跟进的建模或实现调研、夜间批处理。

## 什么时候不要用

| 情况 | 用什么 |
| --- | --- |
| 一次性事实问答、需要引用来源 | `research`（Oracle）或本地搜索 |
| 需要精确模型与档位回执 | Oracle。dot 的 `model_picker_enabled=false`，没有模型/档位回执 |
| 需要可复现的会话导出 | Oracle export。dot 的产物是消息附件，没有 EOF/SHA-256 完整性契约 |
| 低延迟同步返回 | 本地 Codex |
| 本地事实（仓库状态、构建结果、运行证据） | 本地 Codex。**Dots 说"我装好了并截图"，那是它的环境，不是你的仓库** |
| 需要多个独立视角的讨论 | Oracle `consult` / `critic` |

## 下发任务

每条任务消息首行 `【CODEX_DOTS】`，正文五段。`out_of_scope` 是必填的——否则 dot 会按自己的判断扩到下一阶段，阶段边界就失效。

```
【CODEX_DOTS】
stage: S2/官网取证
goal: 拿到 5 个竞品的真实官网与产品页 URL
deliverable: urls.md（含抓取时间、页面标题、是否为真实产品页）
evidence: 每个 URL 至少 1 张截图；标注是否遇到登录墙/反爬
exit: 5 个产品各有 1 个已核实的官网 URL + 证据
out_of_scope: 不下载安装包，不做功能对比
```

阶段划分建议：先广度（有哪些产品）→ 再定位（真实官网）→ 再取证（截图/安装验证）→ 再综合。不要把"取证"和"结论"放在同一阶段，否则无法区分"看到了"和"推断了"。

## 收结果

通过 `/dots/ws` 订阅，事件类型与语义见 `docs/research/dots-delegation-20261024.md`。要点：

- **归属按 `account_user_id`，不按 `role`**。人类和 dot 的消息 `role` 都是 `user`；人类是 `user-...`，dot 是 `calpico-member-...`。未知 uid 报 `unknown`，不要猜。
- **游标用 `(created_at, message_id)`**。`revision` 是 per-subscription 计数，不能跨连接复用。
- 发送带 `request_id` 并持久化；重连不重发。不确定时返回 `DOTS_SEND_UNCONFIRMED`，**不自动重放**。
- 游标补不齐时返回 `DOTS_GAP`，重新拉全量，不要静默跳过。

## 回收标准

和 Oracle 一样，Dots 的输出不是本地结论。回收时区分：

- 它**实际观察到的**（截图、下载件、页面正文、时间戳）；
- 它**推断的**（解释、结论、优劣判断）；
- 它**没做到的**（被反爬挡住、需要授权、需要安装但没装）。

只有第一类能作为本地判断的证据；第二类要标为待核验；第三类要显式保留，不能用完成度话术抹平。

Dots 提出的、能由本地证据回答的问题，Main 自己回答，不要转交用户。只有涉及用户独有的目标、授权、付款、凭据或审美取舍时才需要人类介入。

## 初始化

首次使用需要投递一次 bootstrap，让 dot 知道两种来话方、工作目录约定、阶段格式和回问边界。完整文本见 `chatgpt_oracle/prompts/dots-bootstrap-v1.md`。

- 首次：人工在 DM 里发一次完整 bootstrap（写路径的 API 直接 POST 有 attest 风险，见研究文档）。
- 之后：每条任务消息带 `bootstrap: v1` 摘要行即可，不需要每轮重发全文。
- 恢复：如果观察到它开始用完成度话术、不再标证据，补发 `bootstrap_recovery: v1` 精简版。
